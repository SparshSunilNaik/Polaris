Project Polaris

Autonomy with a chain of command.

A PX4 quadcopter flies a simulated Antarctic survey. Navigation proposes each move, perception and avoidance may revise it, and a deterministic Safety Supervisor has the final word before anything reaches the autopilot. A vision-language model watches the whole time, but it can never steer.

      One command, six hands

      Every 100 ms the navigator proposes a velocity. Each layer below it may pass that command on, rewrite it, or replace it entirely, and only the Safety Supervisor’s output reaches PX4. Pick a situation and follow the command down.

        Paint the risk, watch it react

        Depth Anything turns each camera frame into relative pseudo-depth, which becomes a 3×3 risk grid. Click cells to raise their risk and the real avoidance controller, ported to your browser, decides at 10 Hz. It never trusts a single frame: blockage has to persist across new depth frames before it acts.

        Thresholds from config/reactive_avoidance.json: clear 0.35, caution 0.45, stop 0.62, emergency 0.90. Risk is relative pseudo-depth, not metres. The navigator here always requests 0.40 m/s forward. In flight, a sidestep moves the obstacle out of the centre; here the scene stays frozen, so a held blockage eventually trips the 8 s episode limit and aborts, exactly as the controller would.

        Where the claims stop

        • Simulation only. PX4 SITL and Gazebo Harmonic; nothing here shows physical airworthiness or Antarctic field operation.
        • Depth is relative. Depth Anything gives pseudo-depth, so risk thresholds are not metres and cannot be separation guarantees.
        • Not hard real-time. Python asyncio measures deadline misses but cannot guarantee scheduling.
        • Local, bounded planning. Avoidance reads a 3×3 grid and replanning inserts one nearby waypoint; there is no global planner or occupancy map.
        • Semantics have no authority. A safety strength for evaluation, but the VLM cannot yet adapt the mission.
        • Two runs are not a rate. One retained success and one retained abort say nothing about reliability or generalisation.

        Run it

        Polaris targets PX4 SITL with Gazebo Harmonic and was developed on Apple Silicon. You need a PX4-Autopilot checkout; the repository supplies the Polaris launch scripts, the Antarctic world and macOS setup notes in PX4-Autopilot/docs/MAC_SIM_SETUP.md.

        Keep the simulator running in one terminal and run one MAVSDK-based Polaris app at a time.

        1. Install the Python side

          git clone https://github.com/SparshSunilNaik/Polaris.git
cd Polaris
python3 -m venv .venv
./.venv/bin/pip install -r requirements-depth.txt

        2. Start the Antarctic simulation

          cd PX4-Autopilot
POLARIS_WORLD=antarctica ./scripts/start_polaris_sim.sh

        3. Check the mission, then fly it

          ./.venv/bin/python scripts/mission_demo.py --dry-run --mission polaris-demo-mission --no-display
./.venv/bin/python scripts/mission_demo.py --mission polaris-demo-mission --display

          Add --vlm to run the semantic shadow path; it needs Ollama with qwen2.5vl:7b. --no-flight exercises perception and decisions on the ground.

        4. Run the tests

          PYTHONDONTWRITEBYTECODE=1 ./.venv/bin/python -m unittest discover -s tests -v
