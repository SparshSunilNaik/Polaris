PROJECT POLARIS CODE WALKTHROUGH GUIDE
======================================

PURPOSE
-------
Use this order to show command authority first, then evidence and optional
semantics. The paths and symbols below exist in the current implementation.

1. INTEGRATED MISSION RUNTIME
-----------------------------
Open: scripts/mission_demo.py

MissionDemo.run
  Starts orchestration, waits for readiness, performs takeoff, enables the
  optional observation-time VLM, runs the mission, and always enters terminal
  hover/landing handling.

MissionDemo._mission_loop
  Selects the current waypoint and applies retry, skip, bounded-replan, abort,
  or land policy after each waypoint outcome.

MissionDemo._execute_waypoint
  The highest-value code region. At 10 Hz it snapshots state, updates mission
  bounds, navigation, active perception, deterministic observation, reactive
  avoidance, final safety, command transmission, display, and artifacts.

  Authoritative order:

    LocalGoalNavigator.update
             |
             +--> ActivePerceptionManager.update/observation_hold_command
             |
             v
    ObservationTracker.update        evidence only
             |
             v
    ReactiveAvoidanceController.update
             |
             v
    SafetySupervisor.evaluate
             |
             v
    MissionDemo._send -> MAVSDK -> PX4

  Observation completion is accepted only after command transmission succeeds
  and SafeMotion.hard_override is false.

MissionDemo._project_ego_context
  Builds a one-way RuntimeContextProjection after control decisions. This is an
  observer/annotation path, not an input to SafetySupervisor.

MissionDemo._apply_bounded_replan
  Tries a healthier-viewpoint staging waypoint, then a lateral staging point.
  It accepts only a bounded generated waypoint.

MissionDemo.mission_artifact
  Serializes compressed mission evidence. Note the schema does not include the
  Ego-Context report, VLM result, fused scene, or invocation flags.

run_mission_live and main
  Construct one integrated owner, load checked JSON, handle cancellation and
  exceptions, stop workers, close MAVSDK, print the transient context report,
  and write the artifact.

3. DETERMINISTIC OBSERVATION
-----------------------------
Open: src/polaris/mission/observation.py
Show: ObservationTracker.update, accept_completion, _invalid_reason,
      _reset_dwell.

Inputs include local-NED goal distance, heading error, visual/depth health,
depth stability, centre risk, horizontal speed, collision state, active
perception state, depth frame sequence, and inference timestamp.

Invariant: a fresh observation requires a distinct nonzero depth sequence and
a newer inference timestamp. Dwell follows inference evidence, not repeated
control ticks. This is deterministic observation at a configured waypoint; it
is not proof of visual object detection or metric rock range.

FILES NOT TO OVERCLAIM
----------------------
- Depth output is relative pseudo-depth, not calibrated range.
- Collision injection is a labelled test fixture, not native impact evidence.
- The landing-zone waypoint is surrogate staging before an unvalidated gate.
- JSON artifacts are application evidence, not signed independent ground truth.
